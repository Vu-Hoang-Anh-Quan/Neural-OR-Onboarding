# REINFORCE CartPole-v1 — plan & handoff notes

Goal: implement vanilla REINFORCE (policy gradient, on-policy, full episodes, reward-to-go) for CartPole-v1 in **two variants** — (a) **no baseline** and (b) a **moving-average baseline** — **10 distinct policies** (2 variants × 5 seeds, each seed policy independently initialized), each policy trained independently for **100 epochs**, each epoch **sampling 10 fresh env episodes (instances)**. Per policy, per epoch, compute mean ± std over those 10 sampled instances; plot one line per variant showing that variant's **best-seed policy** (best of its 5 seeds). `results.md` depicts **only the best-seed policy of each variant**, with mean ± std at its best epoch, and the hardware used.
Run from repo root: `conda activate nor && python src/reinforce_cartpole/orchestrator.py [--epochs 100] [--seeds 0 1 2 3 4] [--lr 0.01] [--baseline 0.5] [--device auto]`

## Overview & Invariants
- Env is `nor` (Python 3.11.17). Already installed: `gymnasium 1.4.0`, `torch 2.11.0+cu128`, `numpy 2.4.6`, `matplotlib 3.11.2` (all in `requirements.txt`). Record versions in `results.md` (the orchestrator writes it automatically each run).
- Algorithm invariants (all versions, non-negotiable):
  - **Policies:** a policy is a (variant, seed) pair; the 10 policies are **distinct** — distinct initial weights (init seeded from `torch.manual_seed(policy_seed)`), distinct action stream (own `torch.Generator`), distinct env-reset stream — with `policy_seed = variant_index * 1_000_000 + seed` (variant_index 0 = `no_baseline`, 1 = `moving_avg`). Policies train **independently**, back to back (no cross-policy synchronization; each policy owns its own env).
  - **Epochs:** each policy trains `epochs` (default 100) epochs; **epoch e = 10 fresh env episodes ("instances")** drawn from the policy's own env in one pass (reset → run the full episode → REINFORCE update → next instance). The **epoch return** of a policy = **mean of the 10 instance returns of that epoch** (std = population std, ddof=0, over the same 10).
  - **gamma = 1.0** (no discount — episodes last at most 500 steps).
  - **Reward-to-go:** log-probability of the action taken at step t is weighted by `G_t = sum_{t' >= t} R_{t'}` (sum of the remaining rewards from t to the end of the env episode, **including** `R_t`).
  - **Truncation:** `truncated=True` episodes (survived the default `max_length = 500`) are **kept as-is**: the episode ends there, its reward-to-go is computed and its gradient is **not** zeroed or sign-flipped. Every real step of the episode pays `R = +1.0`, including the final step — gymnasium's `TimeLimit` wrapper only flags `truncated=True` on step 500 and adds **no** terminal bonus — so a surviving 500-step episode has return exactly 500. `terminated` (pole fell) episodes are kept too. The training loop must **never** call `step()` after a `terminated=True` return (post-termination steps return 0.0 and are a no-op).
  - Baseline (`moving_avg` variant only) updates **once per epoch, after the epoch's 10 env episodes finish**: `baseline = baseline * (1 - B) + G_epoch * B` with `B = 0.5` (CLI constant, default 0.5), `G_epoch` = mean of the 10 env-episode returns of the epoch. Initial `baseline = 0.0`. One baseline per policy (5 distinct baselines for `moving_avg`). The baseline is subtracted from reward-to-go in the loss, so it is a per-return constant for every step of every env episode of the epoch.
  - Gradient: single-env-episode full batch, `policy.zero_grad()` → `loss.backward()` → `optimizer.step()`, **one update per env episode, at that episode's end** (classic REINFORCE).
  - **Seeds & reproducibility:** 5 per variant (default `0..4`). Each policy is fully reproducible from its (variant, seed) pair: init weights set by `torch.manual_seed(policy_seed)` at construction, every action sampled from the policy's own `torch.Generator` seeded with the same `policy_seed` (CDF sampling: `u = torch.rand((), generator=...)`, `action = (probs.cumsum(-1) >= u).argmax()` — first bin whose CDF ≥ u; this torch build's `Categorical.sample` takes no generator), and its env reset with seed `policy_seed * 100000 + (e - 1) * per_epoch + i` for instance i of epoch e (e 1-based, i 0-based) — one distinct reset seed per env episode. The baseline needs no seed — its update is deterministic.
- Model (identical for both variants): `nn.Sequential(nn.Linear(4, 64), nn.ReLU(), nn.Linear(64, 2), nn.Softmax(dim=-1))` — obs 4-dim → 2 action probabilities; sampling: exact Categorical draw from the policy's `torch.Generator` (CDF with `torch.rand` — this torch build's `Categorical.sample` has no generator arg); log-prob = `Categorical(probs).log_prob(action)` (float32). Loss = `-(logprob * (G_t - baseline)).sum()` (positive = maximize), i.e. standard REINFORCE on reward-to-go.
- Env: `gym.make("CartPole-v1")` — default (non sutton-barto) reward: `+1.0` for every real step of the episode (the terminal step included), so **return = episode length** (≤ 500). Episodes end by termination (pole fell / cart hit the edge) or truncation (500 steps). Obs/action float32 tensors. No env modification anywhere: no `render_mode`, no custom `max_length`.
- Layout (no `__init__.py`, not a package — same rule as `src/cora/` / `src/tsp_heatmap/`):
  - `src/reinforce_cartpole/policy.py` — the MLP policy class (returns action + logprob).
  - `src/reinforce_cartpole/train.py` — `run_episode(model, optimizer, env, obs, device, generator, baseline)` (one full env episode under one model: action sampling, reward-to-go, the end-of-episode REINFORCE update) and `train(variants=..., seeds=(0,1,2,3,4), epochs=100, per_epoch=10, lr=..., baseline_b=..., device=...)` driving all 10 policies (one policy at a time, independently); returns per-(variant, seed) per-epoch rows, per-policy best-epoch stats, per-variant best-seed policy, per-variant runtimes.
  - `src/reinforce_cartpole/orchestrator.py` — **the only entry point** and the only `setup_logging(log_dir)` caller (root `basicConfig` wins once); bootstraps `sys.path` with the `src/` dir (parents[1]) to reach `utils/logging_utils`; owns the CLI (`argparse`); drives train → writes CSV → plots the PNG → writes `results/reinforce_cartpole/results.md`; logs date, python/package versions, config.
- **Output shape:** one CSV row per `(variant, seed, epoch)`: `variant,seed,epoch,return_mean,return_std,baseline` where the return stats are over the epoch's 10 instance returns (population std `ddof=0`) and `baseline` = the policy's baseline value after the epoch's update (0 for `no_baseline`). Plot: x = epoch 1..`epochs`; **one line per variant** — `no_baseline` in blue, `moving_avg` in red — each showing its **best-seed policy** (the 5-seed policy with the highest best-epoch mean g): line = epoch mean, shaded band = mean ± 1 std over the epoch's 10 instance returns.
- **Best-seed policy (reported in results.md):** per variant, "best policy" = the seed policy with the highest **best-epoch mean g** (best epoch of its `epochs`, earliest on a tie); report that policy's `mean ± std` at its best epoch (1-based), plus its final epoch `mean ± std`.
- Hardware to record: **CPU Ryzen 7 9700 X, GPU RTX 5060 Ti.** `device auto` maps to `cuda` when `torch.cuda.is_available()` (it is — CUDA is present here), else `cpu`. Whatever value the run actually used must be recorded in results.md (it should match `torch.cuda.is_available()` at runtime).

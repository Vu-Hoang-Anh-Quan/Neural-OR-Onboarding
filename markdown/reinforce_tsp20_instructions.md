# REINFORCE TSP-20 (attention) — plan & handoff notes

Goal: train an **attention-based (Transformer-style) neural TSP solver** with **vanilla REINFORCE** (policy gradient, on-policy, full tours, reward-to-go) on random asymmetric TSP-20 instances, in **two variants** — (A) a **moving-average baseline** (const = 0.5) and (B) a **greedy-rollout baseline** (frozen greedy copy; promoted at the end of an epoch when the current policy beats it by at least 5%) — 100 epochs × 100 batches per variant; evaluate both against **LKH-3, NN and NN+2-opt** on 1000 val + 1000 test instances; write `results.md` with the full comparison table and one training-curve PNG per variant.
Run from repo root: `conda activate nor && python src/reinforce_tsp20/orchestrator.py [--epochs 100] [--batches-per-epoch 100] [--batch-size 512] [--lr 1e-3] [--n 20] [--val-n 1000] [--test-n 1000] [--baseline-b 0.5] [--device auto] [--relabel] [--use_eval]` (default lr is **1e-3**, not 1e-4 — see the Gradient bullet / Deviations below; `--use_eval` defaults **OFF** = checkpoint by best epoch-mean *training* return, one checkpoint per variant; ON = the per-epoch val-eval two-checkpoint protocol — see Deviations #4)

Overfit diagnostic (added 2026-11-22): `python src/reinforce_tsp20/orchestrator.py --overfit [--epochs 20] [--batches-per-epoch 100] [--lr 1e-3]` replays the 5 fixed instances in `data/reinforce_tsp20/overfit/` as **every** batch (effective batch = 5 tours per Adam step, `--batch-size` ignored) under the same one-step-per-batch rules, then reports per-instance greedy lengths vs LKH-3/NN/NN+2-opt for those instances (references recomputed live; LKH CSVs untouched). Writes `results/reinforce_tsp20/overfit_results.md` + `<variant>_overfit_returns_curve.png` (the spec-run `results.md`/`*_returns_curve.png` are untouched). `--epochs 20 --batches-per-epoch 100` = 2000 Adam steps × 5 tours = 10k tours — parity with the P4 probe budget.

## Overview & Invariants

### The two variants
- **Variant A — `moving_avg`:** baseline `b` is updated **once per epoch** after its last batch — `b <- b*(1-B) + G_epoch*B`, `B = 0.5` (CLI constant, default 0.5), initial `b = 0.0`; `G_epoch` = the epoch-mean return over all of the epoch's batch returns; subtracted as a per-return constant `(G_t - b)` for every step of the epoch.
- **Variant B — `greedy_rollout`:** baseline = a **frozen greedy copy** of the policy (same architecture; its weights are initialized **identically to the initial policy weights** at the start of training and then never receive gradient updates — only the promotion rule below changes them).
  - **Baseline value per batch:** with the frozen copy (call its weights `baseline_theta`), run a **greedy rollout** on each of the batch's 512 instances (greedy = at every step take the argmax of the logits over unvisited nodes, i.e. the deterministic "most probable path"; no gradients) and take the **mean of its greedy tour lengths** over the batch, `L_base`. The REINFORCE baseline for that batch (in return space, returns being negative tour lengths) is `baseline = -L_base`, subtracted as a per-return constant `(G_t + L_base)` for every step of the batch's tours.
  - **Promotion (the "5% / 95% rounded-up" rule), checked **once per epoch, at the end of the epoch** (after the epoch's last tour has received its update):** with the current policy weights `cur_theta`, compute the mean greedy tour length `L_cur` over **all of the epoch's instances** — the epoch's `batches-per-epoch × batch-size`, i.e. **51,200** in the full default run (100 × 512) — (greedy, no gradients), and with the frozen copy `baseline_theta` compute its mean greedy length `L_base` over the **same epoch's 51,200 instances** (greedy, no gradients). If `L_cur <= ceil(0.95 * L_base)` — i.e. the current policy's greedy tour is **at least 5% better** than the frozen baseline's on the epoch aggregate, with the threshold rounded **up** by `ceil` — then promote: `baseline_theta <- cur_theta` (copy all weights: `load_state_dict`; no optimizer state is involved). Otherwise `baseline_theta` is left untouched. Promotion does **not** change the per-batch REINFORCE baseline above: that `-L_base` is always computed from the frozen copy as it stood at the start of that batch, over the batch's own 512 instances.
  - Record in the run log + `results.md`: the number of promotions, the **epoch** indices at which promotions happened, and the final `L_base` (the frozen copy's mean greedy length over the last epoch's 51,200 instances, as the frozen copy stands at the end of training).
- Both variants: identical architecture, init, data, hyperparameters; only the baseline rule differs. No other algorithmic change.

### REINFORCE invariants (both variants — the only relaxation of the REINFORCE invariants themselves is the update-per-batch rule, Deviations #1–2; the 2026-11-22 per-epoch val eval + best-checkpoint protocol is Deviations #3 and touches no training invariant; the 2026-11-23 `--use_eval` flag, which switches which of the two checkpoint protocols is active, is Deviations #4 and likewise touches no training invariant — the training math, RNG state and draw sequence are unchanged under either)
- **Reward:** `-distance(step)` per step, i.e. the step from the current node to the chosen next node with the **original matrix entry** (do NOT round/scale); the final return of a full tour = **negative tour length** (sum over all n steps including the closing step back to the start). There is **no terminal bonus** — the tour closes exactly at n steps and then ends.
- **Gradient:** `gamma = 1.0`; reward-to-go `G_t = sum_{t' >= t} R_{t'}` (including `R_t`); loss `-sum_t logprob_t * (G_t - baseline)` (positive = maximize). **Update (RELAXED, 2026-11-22 — see Deviations):** **one REINFORCE update per BATCH instead of per tour** — all of a batch's 512 tours are sampled under the batch-start weights, then `zero_grad()` → `loss.backward()` → `optimizer.step()` **once** for the batch loss `-sum_b sum_t logprob_{b,t} * (G_{b,t} - baseline)` (the REINFORCE sum over the batch; the within-batch loss is the same per-tour sum, and the baseline is a per-batch constant anyway). Consequences vs the original per-tour spec: 512 optimizer steps per batch become 1; within a batch the tours are all on-policy w.r.t. the batch-start weights (previously each tour was sampled under already-updated weights); `torch.Generator` draw mapping changes (one `(B, 1)` draw per step instead of one draw per tour).
- **Policy & init:** a policy = one (variant, run) pair — one policy per variant, no seed sweep in this task; init weights with `torch.manual_seed(policy_seed)` just before construction, `policy_seed` per the Training-data seed scheme below (variant index × 1_000_000). Action sampling: log-prob = `Categorical(probs).log_prob(action)`, `action` drawn from the CDF with the policy's own `torch.Generator` seeded `policy_seed` (this torch build's `Categorical` may not accept a generator — use the CDF `argmax` pattern). The baseline needs no seed (its update is deterministic).
- **Greedy decoding (rollout for eval):** at each step take `argmax` over the policy's logits over unvisited nodes; deterministic — no sampling, the std of greedy returns is 0.
- **Training:** 100 epochs × 100 batches × batch-size 512, freshly generated instances each batch (seeded per (epoch, batch) index: `seed = policy_seed*100000 + (epoch-1)*100 + batch`). Adam, `lr = 1e-3` (**was 1e-4**: 1e-4 was the spec value for the mandatory per-tour update; with the relaxed one-step-per-batch update, see the Gradient bullet and Deviations, the orchestrator default is 1e-3 — 10× larger to compensate for 512× fewer optimizer steps). **Record the actual device used** (CUDA here — see Environment) and the **total training wall time** in `results.md`.
- **No truncation / early stop:** tours are always exactly n = 20 steps; the episode "terminates" only when all nodes are visited.

### Deviations from the original spec (recorded, user-approved 2026-11-22; #4 added 2026-11-23)

1. **One REINFORCE update per 512-tour batch instead of one update per complete tour** (the spec's "one REINFORCE update at the end of each complete tour … each tour's loss is backproped and stepped on its own" invariant, formerly line 18, is **relaxed**): all of a batch's 512 tours are sampled under the batch-start weights, then a single `zero_grad() → loss.backward() → optimizer.step()` for the batch loss `-sum_b sum_t logprob_{b,t} * (G_{b,t} - baseline)` (the REINFORCE sum over the batch). Rationale: the per-tour update cost ~11 s per 512-tour batch (epoch cost ~2216.6 s in the BEFORE probe; see the Slow-learning root-cause investigation section below), making the default 100-epoch run ~65 h on this hardware, while the measured epoch cost with batching drops to ~10–27 s (0.10 s/batch vs 11.05 s/batch per-batch wall; numbers in that section and in `results.md` / `log.txt`). Semantics change (documented, not hidden): 512 Adam steps per batch become 1; within a batch the tours are all on-policy w.r.t. the batch-start weights only (previously tour #k was sampled under the weights after update #k-1); the `torch.Generator` draw mapping changes (one `(B, 1)` draw per step instead of one draw per tour). Everything else in the invariant list is unchanged (gamma = 1.0, reward, reward-to-go incl. closing edge, loss form, variants, seeds, architecture, eval).
2. **Default Adam lr raised 1e-4 → 1e-3** in `orchestrator.py` to compensate for the 512× fewer optimizer steps per instance (spec's 1e-4 was specified for the per-tour update; `--lr` still accepts the spec value if desired).
3. **Per-epoch val evaluation + two simultaneous best checkpoints per variant; the final report's four neural rows are inferred from those checkpoints, not from the end-of-training weights** (2026-11-22; replaces the spec's "after training, load the final weights" eval protocol): at the end of **every** epoch the LIVE policy is evaluated on the **val** split (selection set; test stays held out for the final report) — greedy tour length per val instance AND the per-instance min of 128 sampled tour lengths — under `torch.no_grad` with a DEDICATED eval `torch.Generator` (seeded `policy_seed * 1_000_003 + epoch`, never the training generator), so the training math, RNG state and draw sequence are unchanged; both row means are logged. Two best checkpoints per variant are kept **simultaneously** (raw `state_dict` only, no optimizer state) in `src/reinforce_tsp20/checkpoints/` (gitignored): `<variant>_best_greedy.pt` and `<variant>_best_128.pt`, each updated whenever that row's val mean is a new all-epoch best (epoch 1 always writes both). After training, the four neural rows of the final report (both splits) are inferred from those checkpoints only — the greedy row from `<variant>_best_greedy.pt`, the 128-sampled row from `<variant>_best_128.pt` (both loaded into FRESH `TSPPolicy` instances; the live trained policy objects are dropped and GPU memory freed before final inference); the end-of-training weights are never used for the reported rows. The per-epoch 128-sampled row uses per-instance mins over vectorized row-chunked rollout calls (statistically the same quantity as the final-eval B=1-per-instance loop — a different draw schedule, reproducible for fixed weights + generator seed). Rationale: the spec's final-weights table could report a policy strictly worse than one seen mid-training (REINFORCE epochs can regress after their best); the checkpoint protocol costs a few seconds of val eval per epoch (chunked no-grad rollouts sized to fit the ~1 GB free GPU memory measured 2026-11-22 with ollama running: greedy in ≤ 128-instance chunks, sampled in ≤ 1024 rollout-row chunks = 8 instances × 128 samples at the defaults) and makes each neural row report the best-evidence policy for that row's metric instead of the last epoch's weights.
4. **`--use_eval` flag selects the checkpoint protocol; OFF (default) = one best-epoch-mean-training-return checkpoint per variant** (2026-11-23; keeps Deviation #3 behind `--use_eval` and makes the no-eval protocol the default): with the flag OFF, the end-of-epoch protocol is *checkpoint by best epoch-mean TRAINING return* — at the end of every epoch the LIVE policy's raw `state_dict` is re-saved to `src/reinforce_tsp20/checkpoints/<variant>_best_train_return.pt` whenever that epoch's mean training return (the mean over the epoch's 100 batch returns, already computed by the training loop and passed to the hook as `epoch_mean`; return = −tour length, so higher/less-negative is better) is a new all-epoch best (epoch 1 always writes; strict improvement only) — **no eval, no generators, no val data at epoch end**, zero extra wall time. After training, that ONE checkpoint per variant is loaded into FRESH `TSPPolicy` instances and **BOTH** of the variant's report rows (the greedy row and the 128-sampled row, both splits) are computed from that same single checkpoint; the end-of-training weights are still never used for the reported rows. With `--use_eval` ON, the full Deviation #3 protocol runs unchanged (per-epoch val eval with the dedicated per-variant generator + the two simultaneous best `<variant>_best_greedy.pt` / `<variant>_best_128.pt`, one row per checkpoint). Rationale: REINFORCE can regress after its best epoch, so best-training-return checkpointing still guards against reporting the end-of-training weights, but at zero cost (the epoch mean already exists; no per-epoch val rollouts, no GPU-memory budgeting). The training math, RNG state and draw sequence are unchanged under either protocol (the hook still runs after the epoch's last Adam step; the flag-ON eval hook simply ignores the `epoch_mean` kwarg). The report format — row order, columns, percentiles, gap definition, plots — is unchanged; only the header checkpoint-protocol sentence, the `checkpoints, <variant>` lines of `## Runtimes`, and the `use_eval` line of `## Configuration` adapt to whichever protocol was in effect.

### Architecture (all in `attention.py`, new file — no existing Transformer in the repo to reuse)
- **Encoder** (applied to the n node embeddings): 3 blocks on the 20-node sequence, hidden dim **64** throughout, each = [multi-head self-attention with **8 heads** (dim per head = 8, total dim = 64), then a 2-layer FFN 64 → 256 → 64 (GELU, then linear back to 64), with residuals and pre-layer-norms]. Input node feature: `x_i = D[i, :] / 100` (n-dim distance row scaled to ~[0,1]) mapped to dim 64 by a first linear layer (20 → 64).
- **Decoder (action head) — the averaging node:** there is **one special "averaging node"**, distinct from the n graph nodes, and it is the **only** node that creates a query. At timestep `t` of a tour it does two things: (a) it **aggregates the starting node and the current (ending) node** of the partial tour (both from the encoded node set), and (b) **as the query** it attends **over all n unvisited nodes** (visited nodes masked out via `key_padding_mask` or an explicit `-inf` in the softmax). It runs one attention layer (8 heads, dim 64) + FFN (64 → 256 → 64, GELU) + residuals and pre-layer-norms, then a linear head to **n logits** with the visited mask applied, giving the next-node distribution; log-attention weights are not stored — only the distribution. The averaging node re-reads the (unchanging) encoded matrix representations every step, so it is re-constructed at each timestep from the start-node and current-node encodings rather than accumulated across steps.
- All attention/Transformer modules live in **`src/reinforce_tsp20/attention.py`** (encoder block, decoder, mask helpers). No other file defines attention layers.
- **Policy class** in `src/reinforce_tsp20/policy.py`: wraps the encoder + decoder; exposes `act(state) -> (action, logprob, probs)` for one step given (distance matrix or encoded features, current node, visited mask), plus a **greedy rollout** method that unrolls a full tour (returns tour, total distance, per-step log-probs if needed).

## Evaluation

- **Instances:** the fixed 1000 val + 1000 test instances prepared by `dataset.py` (see Data above); every method below runs on **exactly these 2000 instances** (1000 per split), so all table columns are comparable.
- **Methods, per split:**
  - **NN** — `nearest_neighbor(D, start=0)` from `src/heuristics.py`, length via `tour_length(tour, D)`.
  - **NN+2opt** — `two_opt(nearest_neighbor(D, 0), D)` from `src/heuristics.py`, then `tour_length`.
  - **LKH-3** — reference length from `dataset.py` labels (recipe below; `RUNS = 1`, `SEED = 1`).
  - **Per trained variant (A, B):**
    - **greedy** — one deterministic greedy rollout per instance (argmax over unvisited nodes at every step).
    - **128-sampling** — 128 **sampled** full rollouts per instance (actions drawn from the CDF through the policy's `torch.Generator`, which is re-seeded once with the policy seed at the start of the eval phase so eval sampling is reproducible); per-instance value = **min (best) of the 128 tour lengths**.
- **Checkpoint protocols (2026-11-23, see Deviations #4 — selected by `--use_eval`, which defaults OFF):**
  - **Default (flag OFF): best epoch-mean TRAINING return — one checkpoint per variant, no epoch-end computation.** At the end of every epoch, the LIVE policy's raw `state_dict` is re-saved to `src/reinforce_tsp20/checkpoints/<variant>_best_train_return.pt` whenever that epoch's mean training return (the mean of the epoch's 100 batch returns, already computed by the train loop and passed to the hook) is a new all-epoch best (epoch 1 always writes; strict improvement only). No generators, no val/test data touched at epoch end; after training, that ONE checkpoint is loaded per variant and **BOTH** report rows (greedy and 128-sampled, both splits) are computed from it.
  - **`--use_eval` ON: per-epoch val evaluation + two simultaneous best checkpoints (added 2026-11-22, Deviations #3):** at the end of every epoch, the LIVE policy of each variant is evaluated on the **val** split (selection set): mean greedy tour length over the 1000 val instances and mean of the per-instance mins of 128 sampled tour lengths — chunked no-grad rollouts (≤ 128 instances per greedy call; ≤ 1024 rows per sampled call) with a dedicated per-variant eval generator seeded `policy_seed * 1_000_003 + epoch` (never the training generator, so the training math/RNG/draw sequence are unchanged); both row means are logged with the epoch. Two best checkpoints per variant are kept simultaneously in `src/reinforce_tsp20/checkpoints/` (gitignored): `<variant>_best_greedy.pt` (raw `state_dict` of the policy that first achieved the best val greedy mean, re-saved on any later improvement) and `<variant>_best_128.pt` (same for the 128-sampled val mean).
- **Final report sourcing:** after training, the four neural rows on BOTH splits are inferred **from the best checkpoints only** (never the live end-of-training weights): with `--use_eval` ON, greedy row from `<variant>_best_greedy.pt`, 128-sampled row from `<variant>_best_128.pt` (see the ON bullet above); with the flag OFF (default), **both** of a variant's rows from the single `<variant>_best_train_return.pt`. The greedy row is deterministic, so its val mean at the selected epoch equals the val mean in the final table; the 128-sampled row's eval-phase generator contract (re-seeded once per variant with the policy seed at the start of the eval phase) is unchanged.
- **Summary statistics:** per method × split, over the 1000 per-instance lengths: `mean`, `std` (population, ddof = 0), `q1` = 25th percentile, `median`, `q3` = 75th percentile (`np.percentile`, default linear method); **gap vs LKH-3** = `mean - mean(LKH-3 on the same split)` (0 for the LKH row itself by construction). The wall column = total wall-clock seconds for that method over the split's 1000 instances.

## LKH-3 reference (eval instances only)

- LKH-3 is used **only** for the eval instances, never for training data or labels. Binary: `data/LKH-3.0.14/LKH`; it must be run from inside `data/LKH-3.0.14/` (working example `.par` files live there).
- Per instance, write a TSPLIB explicit-matrix problem file into scratch (`data/reinforce_tsp20/eval/scratch/`, removed after the instance finishes):
  `NAME : <name>`, `TYPE : ATSP`, `DIMENSION : 20`, `EDGE_WEIGHT_TYPE : EXPLICIT`, `EDGE_WEIGHT_FORMAT : FULL_MATRIX`, `EDGE_WEIGHT_SECTION`, then the 20 matrix lines `d_{i1} d_{i2} ... d_{i20}` — the **asymmetric** entries as generated (zero diagonal), **no row-index column and no `EDGE_WEIGHT_FIRST_LAST_COLUMN`** (this LKH build rejects both; a row-indexed block is not parsed) — then `EOF`. `TYPE : ATSP` is mandatory — a plain `TSP` misreads an explicit asymmetric matrix and reports a wrong length.
- Per-instance par file in the same scratch dir: `PROBLEM_FILE = <abs path>`, `OUTPUT_TOUR_FILE = <abs tour path>`, `RUNS = 1`, `MAX_TRIALS = 1000`, `SEED = 1`; invoke via `subprocess.run([str(LKH_BIN), str(par_path)], cwd="data/LKH-3.0.14/", ...)` (absolute paths inside the par). ~2000 subprocess launches total — log per-instance and total wall time.
- Read the length from the tour file: `re.search(r"Length\s*=\s*(\d+)", tour_raw)`. **Orientation gate:** parse the tour's node list `t` (0-based) and compute `tour_length(t, D)` and `tour_length(t[::-1], D)`; assert the reported LKH length matches one of the two (LKH's tour direction is arbitrary); if only the reversed matches, store the reversed tour.
- Persist per-instance results to `data/reinforce_tsp20/eval/lkh_val.csv` / `lkh_test.csv`, also carrying `nn_len` and `nn2opt_len` (computed in the same pass, no LKH involved): columns `instance_id, nn_len, nn2opt_len, lkh_len`. On re-run, reuse existing label files unless `--relabel` is passed (idempotent).

## Training data (seed scheme)

- **One policy per variant** (no seed sweep): for variant index `i` in `{0, 1}` (`0` = `moving_avg`, `1` = `greedy_rollout`), `policy_seed = i * 1_000_000`. The policy's initial weights come from `torch.manual_seed(policy_seed)` immediately before construction.
- **Fresh instance per batch**, never reused: batch `(e, j)` (e = 1..E epochs, j = 0..99) of the epoch uses instances generated with `gen_tsp(n, seed, path)` using `seed = policy_seed*100000 + (e-1)*100 + j` (i.e. distinct across all batches of all epochs and across the two variants). Each of the 512 instances per batch is a different instance within that batch (sub-instance indexing is at the implementer's discretion but must be deterministic in the batch seed).
- No training instances are persisted to disk; generation is cheap (ints 1..100, 20×20). The eval instances (below) are the only persisted instances.

## Evaluation instances & baselines

- **Fixed eval sets, generated once by `dataset.py` and persisted** under `data/reinforce_tsp20/eval/` (gitignored):
  - **val: 1000 instances** — `gen_tsp(20, seed = BASE + s, path)` for `s = 0..999`.
  - **test: 1000 instances** — `gen_tsp(20, seed = BASE + 1000 + s, path)` for `s = 0..999`.
  - `BASE` is a base offset **recorded in `results.md`** (so the sets can be regenerated exactly); pick any value that does not collide with the training-seed space (the training batch seeds are ~`policy_seed*100000 + ...`), e.g. `BASE = 1_000_000_000` (record whatever is actually used).
  - File layout: `data/reinforce_tsp20/eval/val/<s>.txt` (raw `gen_tsp` output: line 1 = `20`, then 20×20 ints) and `.../test/<s>.txt`; plus `lkh_val.csv` / `lkh_test.csv` from the LKH pass above.
- **Evaluation runs the same 1000 instances per split for every method**, in this fixed row order: **NN, NN+2-opt, LKH-3, `moving_avg` greedy, `moving_avg` 128-sampled, `greedy_rollout` greedy, `greedy_rollout` 128-sampled**. Each method's row is followed immediately by its sampling row where applicable (greedy first, then its 128-sampling counterpart).
- **Per-variant eval (`--use_eval` OFF, default — 2026-11-23, see Deviations #4):** the weights are NOT "the final weights" — each variant's ONE best-training-return checkpoint (`<variant>_best_train_return.pt` in `src/reinforce_tsp20/checkpoints/`, raw `state_dict`) is loaded into a fresh `TSPPolicy` instance AFTER training, and **BOTH** of the variant's report rows (greedy and 128-sampled, both splits) are computed from that same checkpoint; the end-of-training weights are never used for the reported rows. **`--use_eval` ON (updated 2026-11-22, see Deviations #3):** same idea with the two best checkpoints — each variant's `<variant>_best_greedy.pt` / `<variant>_best_128.pt` (kept simultaneously by the end-of-epoch val eval) are loaded into fresh `TSPPolicy` instances. **Greedy row** (= `<variant>_best_greedy.pt`): one deterministic greedy rollout per instance (argmax over unvisited at each step; no sampling; std = 0 by construction — still report 0.0). **128-sampling row** (= `<variant>_best_128.pt`): resample each instance 128 times (actions drawn from the CDF through the policy's `torch.Generator`, re-seeded once at the start of eval so sampling is reproducible); per-instance value = **min** of the 128 tour lengths.
- **NN / NN+2-opt:** `nearest_neighbor(D, start=0)` and `two_opt(tour, D)` from `src/heuristics.py`. Lengths via `tour_length` (or direct sum over the asymmetric matrix — must use the matrix entries as given, no rounding or scaling).

### Summary statistics (per method × split)

- Over the 1000 per-instance tour lengths of a method on a split: `mean`, `std` (population, ddof = 0), `q1` = 25th percentile, `median` = 50th, `q3` = 75th percentile (linear interpolation, `np.percentile` default).
- **gap vs LKH-3** = `mean_tour_length - mean_LKH3_tour_length` on the same split (so the LKH row has gap 0 by construction; others typically positive).
- **Wall column** = total wall-clock seconds for that method across the split's 1000 instances.

## Slow-learning root-cause investigation (2026-11-22)

Investigation of why the returns curve moved barely at all on a 1–2 epoch full-scale run (final epoch mean ≈ -1010 vs LKH mean 165 on the overfit set). Diagnostic probes (deviation #1 allowed for probes; probes do not ship as code — but the P4 scenario itself, "both variants replaying the 5-instance overfit set for a bounded tour budget," is reachable out of the box since 2026-11-22 via `--overfit` (see run line at the top): the only differences from P4's pinned loop are the 2026-11-22 relaxation (one `optimizer.step()` per batch of 5 tours instead of one per tour) and lr = 1e-3 vs 1e-4):

1. **The architecture does NOT fit the NN potential field.** P1/P2: for an NN start, the greedy tour is exactly the NN tour and the "NN potential" value of a node is its greedy tour length. A 1-epoch full-config training run (per-tour spec code) ended at greedy mean ≈ 960–990 on the overfit instances, i.e. the policy learned ~nothing: it did not move toward the NN potential field (NN mean on those instances 314.4; init greedy mean 980.4).
2. **The optimizer CAN learn — tour budget is the constraint.** P4: the pinned per-tour REINFORCE loop on the 5-instance overfit set (LKH mean 165.0, NN mean 314.4) decreased the overfit training set monotonically from 1017.6 → 601.4 at 10k tours (lr 1e-4), i.e. ~40% of the way from init (980.4) toward NN (314.4) at 10k tours; linear extrapolation of the P4 rate puts the LKH-mean crossing (~165) at ~25k–30k tours. Root cause: REINFORCE's sample-efficiency / cold-start — the default run sees ~51,200 FRESH tours per epoch and ~5.12M tours in 100 epochs, but the per-epoch fresh-instance shift gives little carry-over signal per tour; at lr 1e-4 with one update per tour the 100-epoch budget moves the policy much less than an equivalent overfit budget (this is expected REINFORCE behavior, not a code bug: the architecture and the per-tour code were both verified correct in P1–P4).
3. **Epoch timing** — **BEFORE (per-tour spec update, user config):** 1-epoch full-config probe (`--epochs 1 --batches-per-epoch 100 --batch-size 512 --val-n 8 --test-n 8`, per-tour code, timed branch): variant A `moving_avg` training wall **2216.6 s** (≈ 37 min; the GPU was shared with other work during most of that window); steady-state batch on a clean GPU **11.05 s = gen 0.07 / h2d ~0 / train {rollout 5.78 / loss+bwd 4.95 / opt.step 0.27 / sync ~0.03} / batch wall 11.05** — i.e. ~19.5 min/epoch/variant clean, ~65 h for the full 100-epoch run (both variants + eval). The per-batch cost is 512 sequential batch-1 rollouts + 512 `optimizer.step()` calls (kernel-launch overhead, not FLOPs). **AFTER (batched within-batch update, the new default; same CLI, 1-epoch full-config probe `--epochs 1 --batches-per-epoch 100 --batch-size 512 --val-n 8 --test-n 8`):** steady-state batch wall **0.10 s** per 512-tour batch (gen 0.07 / h2d ~0 / train {rollout 0.01 / loss+bwd 0.01 / opt.step ~0 / sync ~0}; cold j000 batch 0.36 s), epoch walls **10.0 s** (A) and **10.7 s + 8.0 s promotion recompute** (B; B's total training wall incl. the end-of-epoch promotions + final-`L_base` pass: 26.9 s), probe **total wall 74.7 s** (including the 8+8-instance eval). **Per-batch: 11.05 s → 0.10 s (~110×); per-epoch: ~2216.6 s → ~10–27 s (A/B); the full 100-epoch run drops from ~65 h to roughly ~2.5 h** (training ≈ 18 min A + 45 min B + ~80 min eval at 1000+1000, LKH CSVs reused). Note the bottleneck has moved to **CPU instance generation** (~0.07 s/batch ≈ 71% of the epoch wall) — GPU training of all 51,200 tours of an epoch is now ~2.5–2.8 s total (rollout + loss+bwd + step); the constraint before was the 512 sequential batch-1 kernel-launch round-trips per batch × 100 batches, not the FLOPs.

## Code layout

New task dir `src/reinforce_tsp20/` (no `__init__.py`, not a package — same as `src/cora/`, `src/tsp_heatmap/`, `src/reinforce_cartpole/`). Script dirs land on `sys.path` when run as `python src/reinforce_tsp20/<name>.py`; bootstrap `src/` into `sys.path` (parents[1]) to reach `utils/logging_utils`.

- `src/reinforce_tsp20/attention.py` — **all** attention/Transformer code: the encoder block (8-head MHA dim 64 + FFN 64→256→64, residual + pre-layer-norm), the averaging-node decoder (aggregates the start-node + current-node encodings; the single query attends over **all unvisited** nodes; one attention layer 8 heads dim 64 + FFN 64→256→64 + linear head to n logits) and mask helpers (unvisited mask; `-inf` in softmax). No other file defines attention layers.
- `src/reinforce_tsp20/policy.py` — the policy class wrapping encoder + decoder: `act(obs...) -> (action, logprob, probs)` for one step (given the distance matrix, current node, visited mask), and a **greedy rollout** method (unroll a full 20-step tour, argmax at each step, return tour + total distance). Also a sampled-rollout helper (CDF/Categorical draw through a given `torch.Generator`) used by training and eval sampling.
- `src/reinforce_tsp20/dataset.py` — generate + persist the 1000 val + 1000 test instances under `data/reinforce_tsp20/eval/` (val/seeds 0..999, test/seeds 1000..1999, offset `BASE` recorded), and the LKH-3 labeling pass (write `.atsp` + `.par` per instance, run the binary, parse lengths, compute NN / NN+2-opt in the same pass) → `lkh_val.csv` / `lkh_test.csv`. Reuses existing label files unless `--relabel`.
- `src/reinforce_tsp20/train.py` — the per-variant training loop: for each variant build the policy (seeded init), its own Adam optimizer, its own `torch.Generator` (seeded `policy_seed`), and its own baseline state (A: `b = 0.0`; B: a frozen copy of the initial weights via `load_state_dict` from the just-initialized policy). Each epoch = 100 batches of 512 fresh instances; per batch: sample all 512 tours under the batch-start weights, rewards = `-distance(step)` per step, reward-to-go `G_t` per tour, **one REINFORCE update per batch** (RELAXED from per-tour, 2026-11-22 — see Deviations; A: baseline `b`; B: `L_base` from the frozen copy's greedy rollouts over the same batch, computed before the batched update). End of epoch: A updates `b <- b*(1-B) + G_epoch*B` with `G_epoch` = mean of the epoch's 100 batch returns; B runs its end-of-epoch promotion check over all of the epoch's 51,200 instances (promote iff epoch-mean `L_cur <= ceil(0.95 * L_base)`). Records per-(variant, epoch) stats: mean/std of batch returns, baseline value, wall time; returns per-variant epoch stat lists + final policy. Also (added 2026-11-22, see Deviations #3): `_train_variant_body` takes an optional `epoch_end_eval` hook (default `None` — the overfit path passes nothing and is untouched) invoked at the end of every epoch body after the per-epoch timing log as `fn(variant, vi, epoch, policy, epoch_mean=<the epoch's mean batch return>)` (keyword; updated 2026-11-23, see Deviations #4 — the hook may inspect the already-computed epoch mean; the overfit path still passes nothing); `train_variants` (the spec path) threads the hook through; the hook runs AFTER the epoch's last Adam step, so the training math, RNG state and draw sequence are unchanged.
- `src/reinforce_tsp20/orchestrator.py` — **the only entry point**, and the only `setup_logging(log_dir)` caller (root `basicConfig` wins once). Bootstraps `sys.path` with the `src/` dir (parents[1]) to reach `utils/logging_utils`. Owns the CLI (`argparse`: see run line above, plus `--relabel`). Drives: `dataset.py` (eval instances + LKH labels) → `train.py` (both variants, with the end-of-epoch val-eval hooks, see below) → evaluation (all methods on val + test) → **plots the two PNGs inline** → **writes `results.md` inline**. Logs date, python/package versions, config (via a named logger, per repo convention). Also (added 2026-11-22, see Deviations #3): hosts the per-epoch eval machinery — `make_epoch_end_eval(variant, vi, val_D, n_samples, device, log)` builds each variant's end-of-epoch callback (evaluates the live policy on the val split: `chunked_greedy_lengths` (≤128 instances per no-grad rollout call) + `chunked_sampled_min_lengths` (≤1024 rollout rows per call = 8 instances × 128 samples, min per instance) with the dedicated per-variant eval generator re-seeded `policy_seed * 1_000_003 + epoch` each epoch; logs both row means; saves the raw `state_dict` to `src/reinforce_tsp20/checkpoints/<variant>_best_greedy.pt` / `<variant>_best_128.pt` whenever that row is a new all-epoch best, epoch 1 always writing both), `load_best_checkpoints(n, device)` (loads each variant's two checkpoints into FRESH `TSPPolicy` instances → the only policies used for the four neural rows of the final report), and the chunked no-grad rollout helpers. Also (2026-11-23, see Deviations #4): the CLI has `--use_eval` (store-true, default OFF) selecting the epoch-end checkpoint protocol — OFF: `make_best_train_return_hook(variant, device, log)` (saves `<variant>_best_train_return.pt` whenever the hook's `epoch_mean` kwarg is a new all-epoch best, epoch 1 always writing; no eval, no generators) and `load_best_train_return_checkpoints(n, device)` (loads that ONE checkpoint into fresh `TSPPolicy` instances and maps it to BOTH of the variant's report-row slots); ON: the Deviation #3 machinery above (now ignoring the `epoch_mean` kwarg the train loop passes) with `load_best_checkpoints`.
After training it drops the live trained policies from the result dicts and calls `torch.cuda.empty_cache()` before final inference. Checkpoint files live in `src/reinforce_tsp20/checkpoints/` (gitignored, local-only) and are listed with relative paths in the `## Runtimes` section of `results.md`.

Logging: `setup_logging("results/reinforce_tsp20")` (FileHandler + StreamHandler) — log file `results/reinforce_tsp20/log.txt`; other modules use named loggers (`logging.getLogger(__name__)`). No logging config anywhere else.
